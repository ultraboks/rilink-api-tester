Rilink Developer API Tester

Uji langsung endpoint Developer Messaging API milik Rilink dari lokal.

Referensi endpoint ↓
Perhatian: tool ini memanggil API produksi/dev Rilink yang sebenarnya lewat proxy lokal. Mengirim payload text/image/video/audio/document/button/list/carousel yang valid akan benar-benar mengirim pesan WhatsApp nyata melalui device yang terhubung ke token Anda.

1. Koneksi

Ganti ke http://localhost:8000 (atau port php artisan serve Anda) untuk menguji ke instance dev lokal.

Buat token di halaman Developer API → Manage Tokens pada dashboard Rilink (ability messages:send).

2. Skenario Cepat

Uji jalur error tanpa efek nyata (gagal sebelum pesan terkirim ke WhatsApp).

3. Compose Pesan

API menerima salah satu saja — device_id ATAU sender_phone (keduanya required_without satu sama lain). Kalau dua-duanya diisi dan tidak cocok, API menolak dengan 422.

Referensi Endpoint

        

          
Endpoints

          

            POST /api/v1/messages/send

            GET /api/v1/devices
          

          
Auth

          
Laravel Sanctum bearer token, ability messages:send. Role agent ditolak (403). Token yang sudah lewat expires_at otomatis dihapus & ditolak (401).

          
Rate limit

          
60 request / menit per token (throttle:60,1) — berlaku untuk kedua endpoint.

          
Prasyarat

          
Plan tenant harus mengaktifkan developer_api_enabled; kuota harian opsional lewat developer_api_daily_message_limit (berlaku untuk messages/send, bukan devices).

          
Header wajib

          

            Authorization: Bearer YOUR_TOKEN

            Accept: application/json

            Content-Type: application/json (hanya untuk POST)
          

        


        
GET /api/v1/devices

        
    
          
  • Tidak butuh parameter. Mengembalikan hanya device milik tenant dengan status = "connected".
    • 
          
  • Response: {"data": [{"id": 1, "name": "...", "sender_phone": "6281...", "status": "connected"}, ...]}
    • 
          
  • Gunakan id untuk field device_id, atau sender_phone langsung sebagai pengganti device_id pada messages/send.
    • 
        


        
Identifikasi pengirim di messages/send

        
    
          
  • device_id (integer) — dicocokkan langsung ke kolom id device yang connected.
    • 
          
  • sender_phone (string, alternatif) — dicocokkan ke phone_number device; dinormalisasi otomatis oleh server (buang suffix JID :16/@s.whatsapp.net, awalan 0 diganti kode negara default 62, awalan 00 dibuang).
    • 
          
  • Salah satu wajib diisi (required_without satu sama lain). Jika keduanya diisi dan tidak merujuk device yang sama → 422 "The device_id does not match the selected sender_phone."
    • 
        


        
Update 18 Agt 2026: media_url kini wajib untuk button dan list (sebelumnya opsional/diabaikan untuk list). Dikonfirmasi end-to-end sampai ke gateway WhatsApp (Baileys): untuk button hanya format image yang didukung sebagai header; untuk list, image/video/dokumen didukung sebagai header pesan interaktif.


        
Field per type (messages/send)

        
    
          
  • text — text (wajib)
    • 
          
  • image / video / audio / document — media_url (wajib), text (opsional, jadi caption), mime_type, file_name (opsional, biasanya untuk document), ptt (boolean, khusus audio = voice note)
    • 
          
  • button — media_url wajib (jadi header image di pesan tombol), text, title, subtitle, footer opsional, buttons[] (wajib min 1, maks 10 — tiap button: text wajib, id/type/value/url/phoneNumber opsional)
    • 
          
  • list — media_url wajib (jadi header image/video/dokumen di pesan list), text, title, subtitle, footer, button_text opsional, sections[] (wajib min 1, maks 20 — tiap section punya title dan rows[] min 1 maks 10, tiap row: title wajib)
    • 
          
  • carousel — text, title, subtitle, footer, cards[] (wajib min 1, maks 10 — tiap card: title/subtitle/body/footer/media_url opsional, buttons[] wajib min 1)
    • 
          
  • semua type — contact_name dan save_contact (boolean) opsional: jika to belum jadi kontak dan save_contact=true, kontak baru dibuat pakai contact_name.
    • 
        


        
Contoh error

        
    
          
  • 401 — token tidak ada / tidak valid (Sanctum default), atau "This API token has expired." bila expires_at sudah lewat.
    • 
          
  • 403 — "This token is not allowed to use the Developer API." (role agent), atau "This token does not have permission to send messages." (token tanpa ability messages:send).
    • 
          
  • 422 — validasi gagal (field wajib hilang/salah format), device_id/sender_phone tidak valid/tidak connected/tidak cocok satu sama lain, plan tidak mengaktifkan Developer API, atau kuota harian habis. Bentuk: {"message": "...", "errors": {...}}.
    • 
          
  • 429 — melebihi rate limit 60 req/menit.
